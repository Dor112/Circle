# Круг

Самостоятельное приложение для общения небольшой компании: собственные аккаунты, серверы, каналы, личные сообщения, голос, камера и показ экрана. Интерфейс на русском. Работает в браузере на компьютере и телефоне; отдельный клиент устанавливать не нужно.

## Быстрый запуск на Windows

1. Установите **Node.js 24 LTS** с [nodejs.org](https://nodejs.org/).
2. Откройте папку проекта и дважды нажмите **`start.cmd`**. При первом запуске он установит зависимости.
3. Откройте **[http://localhost:3000](http://localhost:3000)**. Зарегистрируйтесь, создайте сервер и нажмите ↗ рядом с его названием, чтобы получить приглашение.

Или выполните в PowerShell:

```powershell
cd D:\Project_Discord
npm.cmd ci
npm.cmd start
```

Окно сервера должно оставаться открытым. Для остановки нажмите `Ctrl+C`. После повторного запуска аккаунты, файлы и история сохранятся в `data/`. Никому не отправляйте эту папку: в ней личная переписка.

**Ссылка localhost работает только на том компьютере, где запущен сервер.** Для закрытого тестирования с друзьями на вашем Windows-ПК используйте **[инструкцию Tailscale и start-friends.cmd](docs/TEST-WITH-FRIENDS.md)**: без покупки VPS и домена. Для постоянного размещения на сервере используйте вариант ниже. HTTP по адресу локальной сети подходит для текста, но браузер не даст доступ к микрофону на обычном `http://192.168…`.

## Запуск для друзей через интернет

Нужны Linux-сервер с публичным IPv4, домен или поддомен и установленный Docker с Compose. Сертификат HTTPS выпускает Caddy, голосовой трафик при необходимости передаёт coturn. Код приложения бесплатный; сервер и домен могут стоить денег у выбранного провайдера. VPS, домен и публичное размещение в этой сессии не создавались.

1. Направьте DNS-запись **A** `chat.example.com` на IPv4 вашего сервера. Если используете DNS-прокси, оставьте запись в режиме **DNS only**: TURN должен обращаться к серверу напрямую. Не добавляйте AAAA, если IPv6 не настроен.
2. Скопируйте проект на сервер, исключив `node_modules`, `data` и `.env`. В Linux выполните в его папке:

```bash
cp .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

   Последняя команда создаёт случайный секрет TURN. Если Node на хосте не установлен, используйте `openssl rand -hex 32`.

3. Откройте `.env` и **добавьте или раскомментируйте**, заменив примеры реальными значениями:

```dotenv
DOMAIN=chat.example.com
PUBLIC_IP=203.0.113.10
TURN_SECRET=ваш_случайный_секрет_из_предыдущего_шага
ALLOW_REGISTRATION=1
```

   Не оставляйте пример IP и не публикуйте `.env`. Compose сам передаст приложению HTTPS-адрес и настройки TURN. `PUBLIC_URL`, `COOKIE_SECURE`, `TRUST_PROXY` вручную для Compose не нужны.

4. Разрешите во внешнем firewall провайдера и firewall сервера:

| Порты | Протокол | Для чего |
|---|---|---|
| 80, 443 | TCP | Сайт и сертификат HTTPS |
| 443 | UDP | HTTP/3, необязательно |
| 3478 | TCP и UDP | TURN |
| 49160–49200 | UDP | Голосовой медиарелей |

   Порт 3000 наружу открывать не нужно. Сохраните доступ по SSH. Сервис TURN в Compose использует `network_mode: host`: этот вариант рассчитан на **Linux VPS**, а не Docker Desktop на Windows. Для VPS с NAT настройте у провайдера соответствующие пробросы; самый простой вариант — VPS с прямым публичным IP.

5. Запустите:

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=50 app caddy turn
```

6. Откройте **`https://ВАШ-ДОМЕН`**. Создайте личный аккаунт и сервер, отправьте друзьям ссылку-приглашение из интерфейса. Они открывают её, регистрируются и подтверждают вступление. Для разговора каждый выбирает один и тот же голосовой канал и нажимает **«Присоединиться к разговору»**, разрешая микрофон. Кнопки камеры и экрана появляются после подключения.

   После регистрации всех друзей можно поставить `ALLOW_REGISTRATION=0` в `.env` и выполнить `docker compose up -d`. Существующие аккаунты продолжат работать. Приглашение в сервер не заменяет регистрацию.

Чтобы обновить приложение, сохраните резервную копию, замените исходники и выполните `docker compose up -d --build`. Для остановки: `docker compose down`. **Не добавляйте `-v`**: этот флаг удаляет тома с данными и сертификатами.

## Что работает

- Регистрация и вход, редактирование отображаемого имени, выход с отзывом сессии.
- Несколько серверов, приглашения на 7 дней, создание текстовых и голосовых каналов владельцем.
- Владелец может исключить участника через список участников и удалить чужое сообщение. Обычный участник может покинуть сервер нажатием на его название.
- Сообщения в реальном времени, история по 50 сообщений, загрузка предыдущих, поиск, редактирование своих сообщений, удаление и шесть реакций.
- Файлы до **10 МБ**, доступные участникам соответствующего канала или диалога. Файлы скачиваются, без небезопасного встроенного отображения HTML.
- Личные диалоги по логину, индикатор набора, присутствие участников сервера.
- Голосовые комнаты и личные звонки с ручным подключением, отключение микрофона/звука, камера **или** показ экрана. Звук экрана отдельно не передаётся. Голос продолжает работать при переходе к текстовым каналам; нажмите имя канала в панели «На связи», чтобы вернуться к звонку.
- Адаптивный интерфейс. На телефоне каналы и профиль открываются кнопкой ☰.

## Границы этой версии

Это самостоятельный проект для небольшой компании, а не полный Discord. В голосовом разговоре максимум **8 участников**. WebRTC использует mesh: каждый участник соединяется с каждым; для больших комнат потребуется SFU, например отдельный медиасервер. История сообщений хранится на вашем сервере без сквозного шифрования. Медиасоединения WebRTC шифруются браузером; отдельного протокола Discord DAVE здесь нет.

Нет Nitro, бустов, магазина, мерча, ботов, веток обсуждений, полноценных настраиваемых ролей, восстановления пароля по почте, push-уведомлений, входящего звонка со звонком-уведомлением, трансляции системного звука и отдельных установщиков для ОС. В личном звонке оба собеседника открывают свой диалог и нажимают ☎. Участники сервера видны в голосовых каналах; у личного звонка есть отдельное состояние подключения, без входящего уведомления.

Браузер и ОС могут ограничивать камеру, показ экрана и фоновую работу на телефоне. Для разных сетей TURN должен быть доступен: одного успешно открывающегося сайта недостаточно для проверки голоса. Запуск Docker и реальный разговор между двумя устройствами нужно проверить в вашей сети — в этой сессии проверены серверный сигналинг и интерфейс, а не передача звука между физическими устройствами.

## Настройки без Docker

Скопируйте `.env.example` в `.env`. `npm start` читает его автоматически.

| Переменная | Значение |
|---|---|
| `PORT`, `HOST` | По умолчанию `3000`, `0.0.0.0` |
| `DATA_DIR` | Каталог SQLite и файлов, по умолчанию `./data` |
| `PUBLIC_URL` | Полный внешний адрес без `/` в конце; обязателен за HTTPS-прокси |
| `COOKIE_SECURE` | `1` для HTTPS, иначе cookie не помечается Secure |
| `TRUST_PROXY` | `1` только при работе за вашим доверенным reverse proxy |
| `ALLOW_REGISTRATION` | `0` закрывает создание новых аккаунтов |
| `STUN_URL` | STUN, по умолчанию `stun:stun.l.google.com:19302` |
| `TURN_URL` | Адреса TURN через запятую |
| `TURN_SECRET` | Общий секрет с coturn, выдаёт временные учётные данные на 24 часа |
| `TURN_USERNAME`, `TURN_PASSWORD` | Альтернатива для внешнего TURN с фиксированными credentials, когда `TURN_SECRET` не задан |

## Резервное копирование

Для обычного запуска остановите приложение и скопируйте **весь `data/`** в безопасное место. Для восстановления верните его до запуска сервера. Резервную копию нельзя делать только из файла `.sqlite` при работающем процессе: актуальные записи могут находиться в WAL.

Для Compose из каталога проекта:

```bash
mkdir -p backups
docker compose stop app
docker compose run --rm --no-deps -v "$PWD/backups:/backup" app sh -c 'tar -czf /backup/krug-backup.tar.gz -C /app/data .'
docker compose start app
```

Команда перезаписывает `backups/krug-backup.tar.gz`: сохраняйте предыдущие копии отдельно. При ошибке резервного копирования всё равно выполните `docker compose start app`. Для восстановления остановите приложение и распакуйте архив в его том через `docker compose run --rm --no-deps -v "$PWD/backups:/backup:ro" app sh -c 'tar -xzf /backup/krug-backup.tar.gz -C /app/data'`. Восстанавливайте в пустой том, чтобы не смешивать разные версии БД; прежний том сначала сохраните. Подробности размещения БД: `docker volume ls`, `docker volume inspect`.

## Проверки и диагностика

```powershell
npm.cmd ci
npm.cmd test
```

Тесты поднимают отдельный сервер на случайном локальном порту с временной SQLite. Проверяют три аккаунта, ограничения доступа, сообщения по Socket.IO, поиск, вложения, реакции, личные диалоги, голосовой сигналинг, исключение участника, выход и сохранение после перезапуска. Пользовательская папка `data/` не используется.

Проверьте вручную с другом:

1. Два разных аккаунта, вступление по приглашению, сообщение и скачивание файла.
2. Два устройства в разных сетях, одна голосовая комната, звук в обе стороны.
3. Камера, показ экрана, выключение микрофона, переход в текстовый канал без потери голоса.
4. Закрытие и открытие браузера, перезапуск сервера, сохранение истории.

Если нет микрофона — проверьте HTTPS, разрешение в браузере и доступ к микрофону в ОС. Если сайт работает, но друга не слышно — проверьте TURN, UDP-порты и `PUBLIC_IP`. Если запросы получают 403 — проверьте совпадение `PUBLIC_URL` с адресом в браузере. Если кнопки каналов скрыты — на узком экране нажмите ☰. Если порт занят — измените `PORT` в `.env` (и локальный адрес в браузере).

## Устройство проекта и анализ Discord

- `server.js` — HTTP API, сессии, SQLite, авторизация и Socket.IO.
- `public/` — клиент без сборки и внешних CDN, WebRTC.
- `tests/app.test.js` — интеграционные сценарии.
- `Dockerfile`, `compose.yaml`, `Caddyfile` — размещение с HTTPS и TURN.
- [docs/ANALYSIS.md](docs/ANALYSIS.md) — исследование установленной оболочки Discord, источники, архитектурные решения и границы выводов.

Код Discord, его графика и шрифты в приложение не включены. Аккаунты и данные Discord не импортируются; это отдельная сеть для вас и ваших друзей.
