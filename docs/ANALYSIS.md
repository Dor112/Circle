## Независимая архитектура Круга

Браузер → HTTP/HTTPS → Express → SQLite (WAL). Socket.IO доставляет сообщения, индикаторы набора, присутствие и SDP/ICE. Браузеры передают аудио и видео через WebRTC напрямую или через coturn. Caddy завершает TLS и проксирует HTTP/WebSocket.

Пароли: scrypt с индивидуальной случайной солью. Сессии: случайные 256-битные cookie с HttpOnly и SameSite=Strict; в БД хранится SHA-256 от токена, срок 30 дней. API и WebSocket проверяют доступ к комнатам. После исключения участника его подписки и голос отзываются. Origin проверяется для записей и Socket.IO. Есть ограничения частоты запросов и размера файлов. HTML сообщений экранируется; скачиваемые вложения не исполняются как страницы приложения.

SQLite и файлы остаются у владельца сервера. Это один процесс с локальным хранилищем; несколько реплик без переделки координации не поддерживаются. Файлы пока не имеют общего дискового лимита и автоматической очистки неиспользованных загрузок; следите за свободным местом. Восстановление забытого пароля, обновление пароля и настраиваемые роли требуют отдельной реализации.

## Проверено

10 автоматизированных интеграционных сценариев в `tests/app.test.js` проходят на Node.js 24.20.0: HTTP, Socket.IO, авторизация трёх пользователей, сообщения, редактирование, реакции, поиск, пагинация, файлы, диалоги, голосовой сигналинг, отзыв доступа, выход, перезапуск с сохранением БД.

Браузерная проверка проводится отдельно и фиксируется в `VALIDATION.md`. Передача реального звука между физическими устройствами и запуск инфраструктуры на внешнем VPS в эту проверку не входят. Совпадение с оригинальным Discord по одинаковым входам/выходам не проверялось: у реализации собственный API и отдельные аккаунты.
