# Голос через LiveKit Cloud

Проект: `wss://the-circle-070y91tb.livekit.cloud`.

После резервной копии `server.js`, `public`, `package.json` и `package-lock.json` распакуйте архив в `/opt/krug`.

Запустите `bash scripts/setup-livekit.sh`. API Key и API Secret вводятся скрыто в консоли VPS. Не присылайте их в чат. Скрипт сохраняет их в `/opt/krug/.livekit.env` с правами владельца и дополняет `compose.override.yaml`, сохраняя настройки Caddy. Если файл имеет неподдерживаемую структуру, скрипт остановится до изменения настроек.

Затем:

```sh
docker compose build app
# Только после успешной сборки:
docker compose up -d --no-deps --pull never app
curl --max-time 10 http://127.0.0.1:3000/api/health
```

На обоих ПК обновите страницу через Ctrl+F5. Войдите разными аккаунтами в один канал. Проверьте звук в обе стороны, отключение микрофона, отключение звука, камеру, показ экрана и выход.

SDK поставляется локально (LiveKit Client 2.23.0, Apache-2.0), без зависимости от CDN. Короткий токен на 2 минуты создаётся сервером для конкретного пользователя и комнаты после проверки сессии и прав. API Secret в браузер не передаётся. В LiveKit устанавливается максимум 8 участников. Удаление участника и выход из аккаунта вызывают запрос отключения в LiveKit; при недоступности его API сервер выводит ошибку подтверждения отключения.

Cloudflare обслуживает сайт и чат. Медиасоединение идёт напрямую к LiveKit Cloud. Старый coturn не требуется для режима LiveKit. Краткое отключение Socket.IO не закрывает установленный звонок LiveKit; после восстановления приложение повторно регистрирует присутствие в канале. Терминальное отключение LiveKit завершает звонок с уведомлением.

Для возвращения к прежнему движку задайте `VOICE_PROVIDER=mesh` в `.livekit.env` и пересоздайте app. Пользовательские данные не меняются.

Без настроенного проекта проверены только локальные тесты. Реальную передачу звука необходимо подтвердить после развёртывания.
