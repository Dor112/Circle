# HTTPS для chat-circle.ru: выпуск на Windows и установка на VPS

Сценарий для вашего Круга: Windows-ПК → win-acme → TXT-запись в Timeweb → сертификат PEM → зашифрованный пакет → VPS `77.91.72.18` → Caddy.

Это обычный публично доверенный HTTPS, не самоподписанный сертификат. Выпуск выполняется с Windows-ПК, поскольку VPS не устанавливает соединение с ACME-сервисами. Ручной сертификат не исправит маршрутизацию VPS: доступ к TCP 443 с устройств друзей всё равно должен работать. Голос и видео после запуска проверяются отдельно.

Ниже точно указано, где выполнять каждый шаг. Команды для Linux вводите по одной строке. Все команды на VPS рассчитаны на пользователя root и проект `/opt/krug`. Уже перенесённая папка `data` не затрагивается.

## 1. Проверка с Windows-ПК

Откройте **PowerShell на своём ПК**, не внутреннюю консоль VPS:

```powershell
curl.exe -4 -I --connect-timeout 10 --max-time 20 https://acme-v02.api.letsencrypt.org/directory
```

Нужен HTTP-ответ без ошибки проверки TLS. Если здесь тоже тайм-аут, сначала нужен рабочий интернет-маршрут с этого ПК: выпуск этим способом пока невозможен. Не используйте флаги отключения проверки TLS.

Создайте папки:

```powershell
New-Item -ItemType Directory -Force D:\KrugTLS\win-acme | Out-Null
New-Item -ItemType Directory -Force D:\KrugTLS\issued | Out-Null
```

## 2. Установка win-acme на Windows

1. Откройте [официальную страницу](https://www.win-acme.com/).
2. Скачайте ZIP для **x64**. Обычная версия `trimmed` подходит для стандартных встроенных плагинов, `pluggable` — если понадобятся дополнительные. Используйте официальный архив, а не переупакованный файл со стороннего сайта.
3. Распакуйте **все файлы ZIP** в `D:\KrugTLS\win-acme`. `wacs.exe` должен лежать прямо в этой папке, не внутри ещё одной вложенной папки.
4. Откройте PowerShell **от имени администратора**:

```powershell
cd D:\KrugTLS\win-acme
.\wacs.exe
```

Не запускайте `wacs.exe` прямо из ZIP.

## 3. Выбор способа выпуска

В интерактивном меню выберите **M — Create certificate (full options)**. Номера последующих пунктов могут отличаться: ориентируйтесь на текст.

| Вопрос | Что выбрать |
|---|---|
| Источник имён домена | Ввести вручную / Manual input |
| Host names | Только `chat-circle.ru` |
| Friendly name | Можно оставить предложенное |
| Разделять на несколько сертификатов | Один сертификат / Single certificate |
| Подтверждение владения доменом | **DNS-01, создать TXT-запись вручную / Create verification records manually** |
| Тип ключа, если спросит | RSA, предложенный размер по умолчанию |
| Где сохранить сертификат | **PEM encoded files (Apache, nginx, etc.)** |
| Папка сохранения | `D:\KrugTLS\issued` |
| Пароль приватного ключа PEM | Без пароля, если предлагается; транспортный пакет мы зашифруем отдельно |
| Дополнительное хранилище сертификата | Не нужно |
| Установка / изменение IIS | Не выполнять дополнительные действия / No additional installation steps |

Программа может задать вопросы в другом порядке. Не выбирайте HTTP-проверку или IIS. Добавлять `www.chat-circle.ru` и `*.chat-circle.ru` для нашего приложения не требуется.

При первом выпуске win-acme предложит условия центра сертификации и email. Прочитайте условия и подтвердите их самостоятельно; укажите свою контактную почту. Помощники Круга не принимают условия за вас.

Если будет предложено создать автоматическое задание продления, не рассчитывайте на него при ручной DNS-проверке: без человека обновить TXT-запись оно не сможет. Автоматическую задачу на этом этапе можно не создавать.

## 4. Добавление TXT-записи в Timeweb

Win-acme покажет конкретные имя и значение. Например:

```text
Record: _acme-challenge.chat-circle.ru
Value: длинная_строка_выданная_программой
```

Это пример формата, а не готовый токен. Используйте **значение текущей попытки**, показанное у вас.

В Timeweb: **Домены и SSL → chat-circle.ru → Редактор DNS → Добавить запись**.

| Поле | Значение |
|---|---|
| Тип | `TXT` |
| Хост | `_acme-challenge` |
| Значение | Точная строка из win-acme |
| TTL | Предложенное значение, например 600 |

В панели Timeweb суффикс `.chat-circle.ru` подставляется справа. Не вводите полный домен ещё раз, иначе получится дублирование. A-запись `chat-circle.ru → 77.91.72.18` оставьте.

Сохраните TXT и **пока не подтверждайте продолжение в win-acme**. В другом окне PowerShell проверьте:

```powershell
Resolve-DnsName _acme-challenge.chat-circle.ru -Type TXT -Server 1.1.1.1
```

Когда появится нужное TXT-значение, вернитесь к win-acme и подтвердите продолжение. При отсутствии записи подождите обновления DNS. Каждый новый выпуск может выдавать новый токен; не запускайте множество повторных выпусков подряд.

Удалите добавленный TXT только после успешного завершения выпуска или когда программа явно попросит. Для следующего продления может понадобиться новое значение.

## 5. Проверка файлов на ПК

В `D:\KrugTLS\issued` обычно будут:

```text
chat-circle.ru-crt.pem
chat-circle.ru-key.pem
chat-circle.ru-chain.pem
chat-circle.ru-chain-only.pem
```

Для Caddy нужны **`chat-circle.ru-chain.pem`** (сертификат с цепочкой) и **`chat-circle.ru-key.pem`** (соответствующий приватный ключ). Одного `chain-only.pem` недостаточно.

Если названия отличаются, не переименовывайте наугад: проверьте, какой common name / префикс вы выбрали, либо покажите только список имён файлов. Содержимое `-key.pem` не присылайте.

## 6. Зашифрованная упаковка на ПК

Для этого я подготовил `D:\Project_Discord\scripts\pack-tls.mjs`. Он проверяет домен, срок и соответствие сертификата ключу, упаковывает два PEM и помощник установки, шифрует пакет и удаляет свою временную незашифрованную копию. Исходные файлы win-acme остаются у вас.

Помощник использует Node.js, установленный для Круга, и OpenSSL из Git for Windows. Путь к OpenSSL на вашем ПК был обнаружен. Установка самого Git находится на [официальном сайте](https://git-scm.com/downloads/win), если на другом компьютере этого файла нет.

В **PowerShell на ПК** выполните:

```powershell
node D:\Project_Discord\scripts\pack-tls.mjs
```

OpenSSL дважды попросит пароль шифрования. Придумайте **новый пароль не короче 20 символов**, не используйте пароль Круга, VPS или Google. Сохраните его в своём менеджере паролей. Ввод может не отображаться. Пароль не попадёт в аргументы команды и вывод помощника.

В `D:\KrugTLS\out` появятся:

```text
krug-certs-ДАТА.enc
krug-certs-ДАТА.enc.sha256.txt
```

**В Google Drive загружайте только `.enc`.** PEM, приватный ключ, пароль и папку win-acme туда загружать не нужно. Текстовый файл с SHA-256 сохраните у себя: хеш понадобится сверить на VPS независимо от скачанной копии.

Пакет использует AES-256-CBC с PBKDF2. Перед расшифровкой обязательно сверяйте SHA-256 из локального вывода/файла: шифрование этого формата само по себе не заменяет проверку целостности.

## 7. Загрузка пакета на VPS через внутреннюю консоль

Разрешите временное скачивание `.enc` по ссылке Google Drive. В ссылке вида `https://drive.google.com/file/d/ID/view` возьмите **ID нового зашифрованного файла**, не старого ZIP проекта.

На **VPS**:

```bash
umask 077
W=$(mktemp -d /root/krug-tls-XXXXXXXX)
cd "$W"
```

Затем:

```bash
read -r ID
```

Вставьте ID файла и нажмите Enter. После этого:

```bash
U='https://drive.google.com/uc?export=download&id='
curl -fL "$U$ID" -o bundle.enc
sha256sum bundle.enc
```

Сравните **все 64 символа** с SHA-256, показанным помощником на Windows. Загружать файл `.sha256.txt` вместе с пакетом и доверять только этой паре недостаточно: сравнивайте со своей исходной локальной копией. Если хеш отличается — не расшифровывайте, проверьте ID/загрузку. Google иногда отдаёт HTML-страницу подтверждения вместо файла.

Расшифруйте:

```bash
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 -in bundle.enc -out certs.tgz
```

Введите тот же пароль шифрования, что на Windows. Не добавляйте пароль к команде. При ошибке `bad decrypt` не продолжайте: проверьте пароль и файл.

Посмотрите состав:

```bash
tar -tzf certs.tgz
```

Ожидаются только:

```text
fullchain.pem
privkey.pem
install-manual-tls.sh
```

Если список соответствует, распакуйте:

```bash
tar -xzf certs.tgz
```

## 8. Установка сертификата и подключение Caddy

В той же **консоли VPS** из папки распаковки:

```bash
bash ./install-manual-tls.sh /opt/krug
```

Помощник:

1. Проверит домен, срок сертификата и совпадение публичных ключей.
2. Проверит наличие проекта и `DOMAIN=chat-circle.ru` в его `.env`.
3. Сохранит прежние конфигурацию и сертификаты в закрытую папку `/root/krug-tls-backup-...`.
4. Поместит новые файлы в `/opt/krug/certs` с правами 600.
5. Добавит `compose.override.yaml` с read-only подключением этой папки к Caddy.
6. Укажет в Caddyfile ручной сертификат.
7. Проверит конфигурацию и пересоздаст **только Caddy**, используя скачанный образ без повторной загрузки.

Если у вас уже существует чужой `compose.override.yaml`, помощник остановится **до изменения настроек**. Если проверка или запуск завершится ошибкой, он попытается восстановить сохранённые файлы и прежний контейнер. Сообщите об ошибке и сохраните путь к резервной копии. Переписку, аккаунты и настройки приложения помощник не меняет.

Итоговый Caddyfile будет таким:

```caddyfile
chat-circle.ru {
    tls /certs/fullchain.pem /certs/privkey.pem
    encode zstd gzip
    reverse_proxy app:3000
}
```

В `compose.override.yaml` добавится только:

```yaml
services:
  caddy:
    volumes:
      - ./certs:/certs:ro
```

Файл override автоматически дополняет основной Compose. Не удаляйте его при последующих обновлениях. Основной `compose.yaml` с вашей папкой данных, диапазоном TURN и образом из GitHub сохраняется.

## 9. Проверка HTTPS

На **VPS**:

```bash
cd /opt/krug
docker compose ps
docker compose logs --tail=30 caddy
```

Проверка локального HTTPS с правильным именем и обычной проверкой сертификата:

```bash
curl --resolve chat-circle.ru:443:127.0.0.1 https://chat-circle.ru/api/health
```

Нужен ответ `{"ok":true}` **без** `-k` и без ошибок сертификата.

На **Windows-ПК**, затем у друга:

```powershell
curl.exe -4 --max-time 20 https://chat-circle.ru/api/health
```

Также откройте `https://chat-circle.ru` в браузере. Предупреждений сертификата быть не должно. Проверьте вход, историю, обмен сообщениями, затем голос, камеру и экран из разных сетей.

Если локальная проверка успешна, а внешняя зависает, выпуск сертификата решён, но остаётся внешний доступ: порты TCP 80/443, firewall Hostkey, маршрут клиента или провайдера. Установка сертификата сама по себе не устраняет эту проблему. Для релея голоса отдельно нужны TCP/UDP 3478 и UDP 49160–49999, как в вашей конфигурации. Успешное открытие сайта не доказывает работу голоса.

## 10. Продление

При ручном сертификате Caddy не продлевает его автоматически. Срок берите из фактического сертификата:

```bash
cd /opt/krug
openssl x509 -in certs/fullchain.pem -noout -dates
```

За 2–3 недели до `notAfter`:

1. На том же Windows-ПК откройте `wacs.exe`, выберите управление продлениями (`Manage renewals`), ваш `chat-circle.ru` и интерактивное продление. Ориентируйтесь на названия пунктов, не случайный номер.
2. При запросе обновите TXT `_acme-challenge` в Timeweb и дождитесь его публикации.
3. После успешного выпуска заново запустите `node D:\Project_Discord\scripts\pack-tls.mjs`.
4. Загрузите новый `.enc`, создайте новую временную папку на VPS и повторите шаги 7–9. Не используйте пакет от старого выпуска.
5. Сертификат и соответствующий ему ключ обновляются вместе. Старый сертификат без причины отзывать не нужно.

Автоматическое задание win-acme не может само выполнить ручную TXT-проверку и перенести сертификат на этот VPS. Для постоянной работы лучше восстановить исходящий HTTPS VPS и вернуть автоматический выпуск Caddy либо отдельно автоматизировать DNS API и защищённую доставку сертификатов.

## 11. Очистка и резервные копии

После успешной установки уберите общий доступ к `.enc` в Google Drive. Исходные PEM и конфигурацию win-acme держите в защищённой локальной папке вне Git и публичных архивов. Рабочие `/opt/krug/certs` и `compose.override.yaml` на VPS сохраняйте.

Временную папку `/root/krug-tls-...` с расшифрованным пакетом можно удалить через файловый менеджер панели или командой только после проверки полного пути. Папки `/root/krug-tls-backup-...` содержат закрытые ключи старых выпусков — учитывайте это при резервном копировании. Приватные ключи и пароль пакета не отправляйте в чат.

## Ограничения проверки этого гайда

Проверены синтаксис Node.js/Bash и цикл шифрования/расшифровки на одноразовом тестовом сертификате. Выпуск настоящего сертификата, DNS-подтверждение и запуск установщика на VPS ещё не выполнялись. Скрипты не принимают условия CA и не создают сертификаты за пользователя.

Источники: [win-acme: начало работы](https://www.win-acme.com/manual/getting-started), [полные варианты и управление](https://www.win-acme.com/manual/renewal-management), [ручная DNS-проверка](https://www.win-acme.com/reference/plugins/validation/dns/manual), [выгрузка PEM](https://www.win-acme.com/reference/plugins/store/pemfiles), [Caddy: ручные сертификаты](https://caddyserver.com/docs/caddyfile/directives/tls).
